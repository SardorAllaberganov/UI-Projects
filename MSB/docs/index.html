4Состояния (state machines)

Три сущности отслеживают свой жизненный цикл независимо. Каждый переход — event-sourced и идемпотентен.

Состояния приглашения
created → pending → completed ↘ expired (>24 ч) ↘ cancelled (действие HR)
Состояния карты
requested → in_production → produced → in_delivery → delivered → distributed → active ↘ delivery_failed → returned_to_branch
Состояния сотрудника (вид для HR)
invited → onboarding (KYC в процессе) ↘ onboarded (KYC пройден, ожидает карту) ↘ active (карта доставлена + активирована) ↘ rejected (KYC провален, требуется эскалация)

6Точки принятия решений и исключения

Реалистичные сценарии сбоев и их обработка системой.

Срок KYC-токена истёк
Сотрудник не может продолжить → обращается к HR → HR создаёт новое приглашение (новое 24-часовое окно).
Паспорт не совпадает с приглашением
Показать ошибку, разрешить 3 повторных попытки. После 3 неудач → блокировка + ручная проверка.
Face liveness не прошёл
До 3 попыток. После 3 неудач → эскалация в отделение для ручного KYC.
Валидация банка не пройдена
Автоматический отказ + уведомление HR. HR связывается с банком для оформления зарплатного договора.
Брак на производстве
Повторная печать в следующей партии. Уведомление HR о задержке на +1 день.
Доставка не состоялась (HR отсутствует)
Повтор на следующий рабочий день. После 2 неудач → курьер хранит карту в депо, HR забирает сам.
HR задерживает выдачу > 7 дней
Напоминающие push-уведомления.
HR задерживает выдачу > 30 дней
Карта автоматически деактивируется; требуется повторный выпуск.

Идемпотентность: каждый переход состояния ключуется по (invite_token, transition_type), чтобы предотвратить дублирование карт при повторных попытках.
Аудит: каждое действие HR, сотрудника, MyID, банковского оператора и курьера логируется с меткой времени и идентификатором инициатора для AML/KYC-комплаенса.

8Открытые вопросы команды

Решения, которые должны быть приняты Продуктом перед релизом v1.

  1. Должны ли события статуса карты отображаться в профиле сотрудника у HR (живой трекинг-таймлайн) или только в виде push-уведомлений?
  2. Экспресс-доставка — есть ли спрос на премиум-тариф со сроком 2 дня вместо 5–7?
  3. Доставка PIN — отдельным конвертом на адрес компании или SMS сотруднику? Нужен анализ безопасности.
  4. Можно ли разрешить сотрудникам пользоваться картой через Apple Pay / Google Pay сразу, пока физическая карта производится?
  5. Массовая загрузка (Excel со списком 50+ сотрудников) — добавлять в v1.1?
