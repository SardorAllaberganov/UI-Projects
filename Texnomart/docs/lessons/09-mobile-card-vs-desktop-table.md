# 09. Таблица на десктопе, карточки на мобильном — паттерн dual-render

## Цель
Сохранить плотную табличную раскладку на десктопе/планшете и одновременно дать на мобильном (<640 px) чистую карточную раскладку с пальце-удобными целями нажатия — без переписывания данных, без двух разных мест истины.

## Контекст / Проблема
В дашборде ([`src/pages/Dashboard.tsx`](../../src/pages/Dashboard.tsx)) блок «Последние заявки» — это `shadcn <Table>` с шестью колонками (`№`, `Клиент`, `Сумма`, `Партнёр`, `Статус`, `Время`). На десктопе он читается отлично. На 390 px (iPhone 12 / 13 / 14) колонки сжимаются настолько, что цифры суммы упираются в имя партнёра, статус-бейдж переносится в две строки, а строка целиком становится «прыгающим зоопарком» из крошечных ячеек.

Варианты, которые НЕ подходят:
- **Горизонтальный скролл строки**. shadcn `<Table>` уже обёрнут в `overflow-auto`, но горизонтальный скролл — это разрыв ментальной модели в админ-приложении: пользователь ожидает листать вниз, а не вбок. На мобильном список заявок — это «лента», не таблица
- **Скрывать колонки на узких экранах**. Часть данных пропадёт — оператору всё равно нужно видеть и клиента, и сумму, и статус
- **Сжимать padding / font-size**. Можно выгадать ~80 px, но сенсорный таргет всё равно остаётся в пределах одной табличной строки высотой 36 px — это меньше рекомендованных 44 px

## Решение
**Параллельный рендер двух представлений одних и тех же данных, переключаемых через Tailwind responsive utilities:**

```tsx
<CardContent className="p-0">
  {recentApps ? (
    <>
      {/* desktop / tablet */}
      <div className="hidden sm:block">
        <Table>
          <TableHeader>{/* ... */}</TableHeader>
          <TableBody>
            {recentApps.map((app) => (
              <TableRow key={app.id} onClick={() => navigate(`/applications/${app.id}`)} className="cursor-pointer hover:bg-muted/50">
                {/* ID / Клиент с аватаром / Сумма / Партнёр / Статус / Время */}
              </TableRow>
            ))}
          </TableBody>
        </Table>
      </div>

      {/* mobile */}
      <ul className="space-y-2 p-3 sm:hidden">
        {recentApps.map((app) => (
          <li key={app.id}>
            <button
              type="button"
              onClick={() => navigate(`/applications/${app.id}`)}
              className="block w-full rounded-lg border bg-card p-3 text-left transition-colors hover:border-foreground/20 hover:bg-muted/30 focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-brand focus-visible:ring-offset-1"
            >
              <div className="flex items-start justify-between gap-2">
                <p className="min-w-0 truncate text-sm font-semibold">{app.clientName}</p>
                <StatusBadge status={app.status} className="shrink-0" />
              </div>
              <p className="mt-0.5 truncate text-xs text-muted-foreground">
                {app.partnerName} · {formatRelative(app.createdAt)}
              </p>
              <p className="mt-2 text-base font-semibold tabular-nums">
                {formatUZS(app.amount)}
              </p>
            </button>
          </li>
        ))}
      </ul>
    </>
  ) : (
    /* общий Skeleton — не дублируем по брейкпоинтам */
    <div className="space-y-2 p-4">
      {Array.from({ length: 6 }).map((_, i) => (
        <Skeleton key={i} className="h-10 w-full" />
      ))}
    </div>
  )}
</CardContent>
```

Ключевые решения внутри карточки:
- **Триада данных, без подписей.** Имя + статус-бейдж (строка 1), партнёр + относительное время (строка 2, мелкий muted), сумма (строка 3, крупная, `tabular-nums`). Каждая строка очевидна по контексту — лейблы `Сумма / Партнёр / №` визуально шумят и не дают доп. ценности
- **№ заявки убран из карточки.** Это lookup-id; на ленте он не нужен — пользователь идентифицирует заявку по клиенту + сумме + банку. Номер появится на странице деталей
- **Один `<button>` на всю карточку.** Семантически правильно (это «кнопка-навигация»), keyboard-focusable, имеет brand-фокус-ring. `<li>` сам по себе не интерактивный — нельзя вешать `onClick` без role/tabIndex и обработки клавиш
- **Контейнер `<ul>` + `<li>` сохранён** для семантики списка (важно для screen-reader: «6 items»). Реальный кликабельный элемент — внутренний `<button>`
- **Визуальное разделение карточек:** `space-y-2` (8 px зазор) + `rounded-lg border bg-card`. Двойная рамка («карточка в карточке») здесь читается как «маленькие плитки внутри секции», а не как ошибка. Если когда-то захочется убрать внешнюю рамку — сделать `border-0 shadow-none` у родительского `Card` на мобильном
- **Высота `Skeleton` одинаковая** в обоих режимах (рендерится один блок без `sm:hidden`/`hidden sm:block`). Лишний рендер на брейкпоинт-смене не нужен

## Принципы
- **Брейкпоинт `sm` (640 px), не `md`.** Граница «таблица читается» проходит примерно на 6 колонках × ~80 px = 480 px содержимого + табличный padding ≈ 600 px. На `sm:` устройствах (планшеты-портрет) таблица ещё нормально живёт; на телефонах — нет
- **Один источник данных, два представления.** Никаких отдельных state/queries для мобильной версии. Это позволяет легко добавлять/убирать поля: один раз изменить тип строки — и оба рендера подтянутся
- **Mobile-card-list — это не «упрощённая таблица», это другой UI.** На карточке акцент идёт на ключевые поля (что? сколько? когда?), а не на компактное перечисление по колонкам. Не пытаться повторить «номер заявки + 5 колонок справа налево»
- **Skeleton и empty-state — общие.** Они вертикальные, под `<sm`/`>=sm` выглядят одинаково. Дублировать их по брейкпоинту = технический долг без выгоды
- **Хит-таргет ≥ 44×44 px на мобильном.** Карточка с `p-3` + 3 строки контента легко даёт ~80 px высоты — комфортно для пальца. Табличная строка `h-9` (36 px) на мобильном **не** комфортно

## Чего не делать
- ❌ Не использовать `MediaQuery`-хуки (`useMediaQuery`, `useIsMobile`) для переключения **рендера**. Это даёт layout shift при гидратации (на SSR — мерцание; в SPA — задержку до первого `useEffect`). Tailwind utilities делают переключение через CSS, ноль JS — идеально для статичного брейкпоинта
- ❌ Не делать на мобильном `card-grid` (`grid-cols-2`) — заявки длинные, статус-бейджи разной ширины, в две колонки получится «лестница». Один столбец, full-width
- ❌ Не выкидывать `<ul>`/`<li>` ради `<div>`. Список заявок — это семантически именно список; screen-reader ожидает услышать «list, 6 items» и навигироваться по нему стрелками
- ❌ Не дублировать обработчики (`onClick`) на разных уровнях. Только `<button>` внутри `<li>`. `<li>` без интерактивности
- ❌ Не пытаться «адаптировать» таблицу через `display: block` на `<TableCell>` (классический CSS-anti-pattern). Получается ровно та же карточка, но с лишней семантикой `role="cell"` без таблицы — для screen-reader это бред
- ❌ Не добавлять второй внешний `<Card>` на мобильном вокруг ленты карточек. У карточек уже есть свой border-radius + border; внешний `Card` обеспечивает только заголовок секции (`CardHeader`) и общий контейнер
