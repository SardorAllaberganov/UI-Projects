# 06. Контент во всю ширину

## Цель
Снять ограничение по ширине с основной области контента — таблицы и дашборды должны использовать всё доступное пространство.

## Было
```tsx
<main className="flex-1">
  <div className="mx-auto w-full max-w-screen-2xl p-4 md:p-6">
    <Outlet />
  </div>
</main>
```

`max-w-screen-2xl` = `1536px`. На широких мониторах (1920px+, 2560px+) контент центрировался с большими полями по бокам — таблицы заявок и графики оставались узкими.

## Стало
```tsx
<main className="flex-1">
  <div className="w-full p-4 md:p-6">
    <Outlet />
  </div>
</main>
```

`mx-auto` и `max-w-screen-2xl` убраны. Контент растягивается на всю оставшуюся после сайдбара ширину.

## Принципы
- Админка ≠ маркетинговая страница. У админок нет «удобной длины строки», у них есть «вся доступная сетка таблиц/графиков». Ограничивать ширину обычно не нужно.
- Если в будущем понадобится длинная читаемая колонка (например, страница «Изменения политики»), ограничивай ширину на уровне самой страницы (`max-w-3xl mx-auto`), а не в `AppLayout`.
- `p-4 md:p-6` оставляет внутренние поля от краёв окна — не уменьшай ниже `p-4`, иначе на мобиле контент уезжает в самый край и пропадает воздушность.

## Когда вернуть ограничение
- Если появится страница профиля сотрудника или одиночной заявки, где длинные текстовые поля выглядят растянутыми.
- На странице вход/онбординг (одна форма по центру).

В этих случаях ограничивай **внутри страницы**, не в shell'е.
