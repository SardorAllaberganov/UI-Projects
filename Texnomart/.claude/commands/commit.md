Group uncommitted changes by topic and create separate commits for each group, then push.

### Step 1: Analyze Changes
Run `git status` and `git diff --stat HEAD` to see all modified/untracked files.

### Step 2: Group by Topic
Classify each changed file into a topic group:

**Grouping rules (in priority order):**
1. **Pages** — `src/pages/*`
2. **Layout** — `src/components/layout/*`
3. **Shared primitives** — `src/components/shared/*`
4. **Charts** — `src/components/charts/*`
5. **shadcn primitives** — `src/components/ui/*`
6. **Stores / Hooks** — `src/stores/*`, `src/hooks/*`
7. **Data layer** — `src/api/*`, `src/mock/*`
8. **i18n** — `src/i18n/*`
9. **Routing / App entry** — `src/app/AppRoutes.tsx`, `src/app/AppProviders.tsx`, `src/App.tsx`, `src/main.tsx`
10. **Constants / Types / Lib** — `src/lib/*`, `src/types/*`
11. **Styles** — `src/index.css`, `tailwind.config.js`, `postcss.config.js`
12. **Config** — `package.json`, `vite.config.ts`, `tsconfig*.json`, `eslint.config.js`, `components.json`
13. **Docs** — `docs/*`, `*.md` (excluding `CLAUDE.md` and `.claude/`)
14. **Project Config** — `CLAUDE.md`, `.claude/*`, `.gitignore`

If files are tightly coupled for one logical change (e.g. a new page + its route + nav entry + i18n keys), group them together — that beats slicing by folder.

### Step 3: Present Plan
Show the proposed commit groups:

```
Group 1: [topic] — N files
  - file1.tsx
  - file2.tsx
  Commit message: "type(scope): description"

Group 2: [topic] — N files
  - file3.tsx
  Commit message: "type(scope): description"
```

Wait for user approval before proceeding.

### Step 4: Commit Each Group
For each approved group, in dependency order:
1. `git add <specific files>`
2. `git commit -m "<message>"`

**Commit message format:**
- Prefix: `feat:`, `fix:`, `refactor:`, `docs:`, `chore:`, `test:`, `style:`
- Include scope where useful: `feat(applications): add status filter chips`, `fix(sidebar): keep mobile menu button visible on iOS`
- First line under 72 chars
- Add body if needed for context
- NEVER include "Co-Authored-By", "Generated by", or any AI/Claude signature

### Step 5: Push
```bash
git push
```

### Rules
- NEVER use `git add -A` or `git add .` — always add specific files
- NEVER commit `.env`, `node_modules/`, `dist/`, or `docs/*.pdf` (the ТЗ stays local unless explicitly asked)
- Never include AI attribution lines in commit messages
- If a pre-commit hook (typecheck/lint) fails, stop and report — don't `--no-verify`
- If unsure about grouping, ask the user
- If there are merge conflicts, stop and report
