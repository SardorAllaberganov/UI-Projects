# 06. Internationalization (RU / UZ)

## Setup
- **Library**: `react-i18next` + `i18next` + `i18next-browser-languagedetector`
- **Config**: [`src/i18n/index.ts`](../../src/i18n/index.ts)
- **Locale files**: [`src/i18n/locales/ru.json`](../../src/i18n/locales/ru.json) and [`uz.json`](../../src/i18n/locales/uz.json)
- **Default namespace**: `translation` (single-file per locale, nested keys by feature)

## Locale strategy
- **RU is canonical**. All new keys land in `ru.json` first
- **UZ is scaffolded** — `uz.json` is currently `{}`. When the user switches to UZ via the LanguageSwitcher or UserMenu, missing keys fall back to RU (`fallbackLng: "ru"` + `returnEmptyString: false`)
- Detection order: `localStorage["texnomart.locale"]` → `navigator.language` → `<html lang>`
- Switching language: Zustand store `ui.store.ts` → `useLocaleSync` hook syncs i18next → sets `<html lang>`

## Adding new strings

1. Pick a namespace. We use feature-rooted nesting:
   ```jsonc
   {
     "nav":        { "dashboard": "…", "analytics": "…" },        // sidebar labels
     "actions":    { "create": "Создать", "save": "Сохранить" },  // verbs
     "common":     { "loading": "Загрузка…", "empty": "Нет данных" },
     "status":     { "approved": "Одобрена" },                    // application status
     "userStatus": { "active": "Активен" },
     "role":       { "admin": "Администратор" },
     "table":      { "id": "№", "client": "Клиент" },             // shared table headers
     "<feature>":  { "title": "…", "subtitle": "…", "table": { … }, "filters": { … } }
   }
   ```
2. Use it in code:
   ```tsx
   const { t } = useTranslation();
   t("dashboard.title");
   t("applications.table.term_months", { count: 12 });  // → "12 мес."
   ```
3. Don't add the same key to `uz.json`. Leave it absent — it falls back. UZ translations will be done in one pass later

## Pluralization
- Use i18next's count plurals: key suffix `_one` / `_few` / `_many` / `_other`
- Russian uses `_one / _few / _many / _other`. Example:
  ```jsonc
  "term_months_one": "{{count}} месяц",
  "term_months_few": "{{count}} месяца",
  "term_months_many": "{{count}} месяцев"
  ```
- Currently we use the simpler `term_months: "{{count}} мес."` short-form abbreviation; switch to full plurals when the UI calls for it

## Formatters (locale-aware)
Locale-aware number/date/currency formatting lives in [`src/lib/utils/formatters.ts`](../../src/lib/utils/formatters.ts):

- `formatUZS(amount)` → `"12 500 000 сум"`
- `formatNumber(value)` → `Intl.NumberFormat("ru-RU")`
- `formatPercent(value)` → `Intl.NumberFormat("ru-RU", { style: "percent" })`
- `formatDate(date, pattern?)` → `date-fns` with `ru` locale
- `formatRelative(date)` → "5 минут назад", "вчера"
- `formatPhone("998901234567")` → `"+998 90 123 45 67"`
- `formatPinfl("...")` → 14-digit string as-is (passthrough placeholder)

When UZ formatters are added later, branch on the active locale inside these helpers.

## Don'ts
- ❌ Hardcode user-facing text in JSX (`>Создать<` → `>{t("actions.create")}<`)
- ❌ Concatenate translated fragments (`t("from") + " " + t("date")`) — use a single key with interpolation
- ❌ Add new top-level namespaces frivolously. Prefer extending existing ones (`actions`, `common`, `table`, `status`)
- ❌ Translate placeholder content or mock data (Uzbek names, bank names, branch names — keep them as-is)
